# CALL & RENT — نظام إدارة عمليات التشغيل

> Drive Your Dreams, Discover Istanbul

تطبيق ويب بهوية الشركة (الأزرق الكحلي #1B2A56) لإدارة عمليات شركة تأجير السيارات في إسطنبول: لوحة تشغيل يومية، عقود، أسطول،
صندوق واتساب مع ردود بأسلوب الشركة، وسجل تدقيق لكل أمر.

مبني ليكون **واجهة موحّدة أمام الأنظمة الخارجية** (eganis أولاً، ثم أي نظام آخر لاحقاً:
محاسبة، موارد بشرية، تحليلات)، ويُعرّض نفس العمليات عبر **خادم MCP** حتى تستطيع
مخاطبة النظام من Claude مباشرة: «شو المتأخر اليوم؟» ، «مدّد عقد CR-2041 يومين» ،
«اقترح رد على آخر رسالة من أحمد».

---

## 1) التشغيل السريع

```bash
npm install
cp .env.example .env        # ثم عدّل APP_TOKEN على الأقل
npm run seed                # بيانات أولية: ردود مدرَّبة + محادثة تجريبية
npm start                   # http://localhost:3000
```

يعمل النظام افتراضياً بوضع تجريبي (`EGANIS_DRIVER=mock` و `WHATSAPP_DRIVER=mock`)
حتى تتمكن من تجربة كل شيء قبل ربط الحسابات الحقيقية.

المتطلبات: Node.js إصدار 22.5 أو أحدث (يستخدم SQLite المدمج في Node — بلا قاعدة بيانات خارجية).

عند فتح اللوحة، اضغط **«رمز الدخول»** وأدخل قيمة `APP_TOKEN` من ملف `.env`.

## 2) بنية النظام

```
المتصفح (لوحة عربية RTL) ─┐
                          ├─► خادم التطبيق ─┬─► موصل eganis  (mock | api | browser)
Claude عبر MCP  ──────────┘   (Node HTTP)   ├─► موصل واتساب  (mock | cloud)
                                            ├─► صياغة الردود (Claude API)
                                            └─► SQLite: محادثات، ردود مدرَّبة، ملاحظات، سجل تدقيق
```

| المجلد | المحتوى |
|---|---|
| `src/connectors/eganis/` | الربط مع eganis: `mock` تجريبي، `api` عبر Web Service، `browser` عبر أتمتة المتصفح |
| `src/connectors/whatsapp/` | الربط مع واتساب: `mock` محاكاة، `cloud` عبر WhatsApp Cloud API |
| `src/core/` | منطق العمليات (لوحة اليوم، الأوامر)، صندوق الوارد، محاسبة المستأجرين، سجل التدقيق |
| `src/ai/reply.js` | صياغة الردود بأسلوب الشركة اعتماداً على الردود المدرَّبة وسياق العميل |
| `src/routes/` | مسارات الـ API |
| `src/mcp/server.js` | خادم MCP الذي يمنح Claude الوصول للعمليات |
| `public/` | لوحة التحكم (عربية، اتجاه RTL، بلا خطوة بناء) |
| `public/logo-mark.svg` | شعار الشركة داخل التطبيق — استبدله بملفك الرسمي متى شئت |

**قاعدة ثابتة:** كل بيانات التشغيل (العقود، المركبات، الحجوزات، الحركات المالية، المستندات والصور) تبقى مصدرها eganis —
النظام لا ينسخها ولا يصبح مصدراً موازياً. ما يُخزَّن محلياً فقط: المحادثات، الردود
المدرَّبة، الملاحظات، وسجل التدقيق.

## 3) ربط eganis

للنظام ثلاثة أوضاع، تختارها بـ `EGANIS_DRIVER`:

### أ) `api` — الأفضل إن توفّر لك Web Service
eganis يوفّر Broker Web Service للتكامل. اطلب من مزوّد الخدمة توثيق الـ API وبيانات
الدخول، ثم:

```bash
cp config/eganis.example.json config/eganis.json
```

عدّل في الملف: مسار تسجيل الدخول، مسار كل عملية (`listContracts`، `extendContract`، `listLedgerEntries`، `listDocuments`، `downloadDocument` …)،
وخريطة الحقول (`maps`) لتحويل أسماء حقول eganis إلى أسماء النظام. ثم في `.env`:

```
EGANIS_DRIVER=api
EGANIS_BASE_URL=https://your-eganis-host
EGANIS_USERNAME=...
EGANIS_PASSWORD=...
```

لا حاجة لتعديل أي كود — الملف وحده يكفي لأن كل تركيب من eganis يختلف في المسارات.

### ب) `browser` — عندما لا يتوفّر API (يكفيه دخولك العادي للوحة)

**تلقائي بلا إعداد:** يفتح لوحتك، يتعرّف على صفحاتها من أسمائها التركية
(`Sözleşmeler`، `Araçlar`، `Rezervasyonlar`، `Müşteriler`، `Cari Hesap`)، ثم يفهم
أعمدة الجداول بالمطابقة: `Sözleşme No` → `no`، `Depozito` → `deposit`،
`Para Birimi` → `currency`… ويحوّل الأرقام التركية (`3.000,50`) والتواريخ
(`18.08.2026`) والحالات (`Açık` → مفتوح · `Kirada` → مؤجّرة) إلى صيغ التطبيق.
المنطق كله في `src/connectors/eganis/auto-map.js` ومغطّى باختبارات.

كل ما يلزم في `.env`:

```env
EGANIS_DRIVER=browser
EGANIS_BASE_URL=https://panel.eganis.com.tr
EGANIS_USERNAME=...
EGANIS_PASSWORD=...
```

وإن أردت التحكم اليدوي، عرّف `browser.pages` في `config/eganis.json` فيتقدّم على الاكتشاف.

**من الجوال بلا كمبيوتر:** [`docs/deploy-mobile.md`](docs/deploy-mobile.md) —
نشر من المتصفّح بلا سطر أوامر.

التثبيت للتشغيل المحلي:

```bash
npm i playwright   # أو استخدم playwright-core المرفقة مع Chrome مثبَّت على النظام
```

**لضبط المحدِّدات يدوياً أو تشخيص لوحة غير معتادة** — الخطوات بالترتيب (على كمبيوتر فيه شاشة، ثم تُنقل النتيجة للخادم) —
الدليل المفصّل للمستخدم: [`docs/eganis-browser-steps.md`](docs/eganis-browser-steps.md)

```bash
# 1) سجّل دخولك بيدك مرة واحدة — يفتح متصفّحاً مرئياً ويحفظ الجلسة
npm run eganis:inspect -- login

# 2) اكتشاف الصفحات ووصف جداولها تلقائياً (يكفي عادةً)
npm run eganis:inspect -- auto

# عند الحاجة: سرد كل الروابط، أو فحص صفحات تحدّدها بنفسك
npm run eganis:inspect -- menu
npm run eganis:inspect -- scan /sozlesmeler /araclar
```

يستخدم المستكشف متصفّح Chrome المثبَّت على جهازك إن وُجد، فلا يحتاج تنزيل متصفّح إضافي.
وتُخفى أرقام الهواتف والهويات تلقائياً من العيّنات (يعطّلها `--raw`).

المخرجات كلها تبقى عندك في `data/eganis-inspect/` (وصف الجداول + لقطات + HTML)،
ومنها تُكتب المحدِّدات في `config/eganis.json`.

**لماذا تسجيل الدخول اليدوي؟** الجلسة تُحفظ في `data/eganis-session.json` ويعيد السائق
استخدامها، فلا تحتاج وضع كلمة سر eganis في أي ملف، ويعمل الربط حتى لو كانت اللوحة
تطلب رمز تحقق. الملف يحوي كوكيز جلستك — عامله معاملة كلمة السر ولا ترفعه لأي مكان عام
(مجلد `data/` مستثنى أصلاً من git).

عند انتهاء الجلسة (بعد أيام عادةً) أعِد تنفيذ الخطوة ١. أو ضع `EGANIS_USERNAME` و
`EGANIS_PASSWORD` في `.env` على خادمك مع محدِّدات `usernameSelector`/`passwordSelector`
فيسجّل الدخول تلقائياً.

### فحص الربط في أي وضع

```bash
npm run eganis:check
```

يجرّب تسجيل الدخول ثم كل عملية، ويقول لك ما نجح وما فشل ولماذا، وأي الحقول وصلت
فارغة وتحتاج تعديل الخريطة (بما فيها حقل العملة `currency`). قراءة فقط — لا ينفّذ أي تعديل.
أرسل لي مخرجاته وأزبّط ما فيها.

### ج) `mock` — الوضع الافتراضي للتطوير والعرض

> ملاحظة مهمة: ما بُني هنا هو **طبقة الربط الجاهزة**، وليس ربطاً فعلياً بحسابك.
> الربط ينفَّذ على جهازك/خادمك لأن eganis لا يُفتح من بيئة التطوير.
> لطلب الـ API من مزوّد البرنامج: راجع [`docs/eganis-api-request.md`](docs/eganis-api-request.md)
> — فيه رسالة تركية جاهزة للإرسال.

## 4) ربط واتساب الشركة

يستخدم النظام **WhatsApp Cloud API** الرسمي من Meta (الطريقة المسموح بها لحسابات
الشركات؛ الحلول غير الرسمية تعرّض الرقم للحظر).

الخطوات:
1. أنشئ تطبيقاً على [developers.facebook.com](https://developers.facebook.com) وأضف منتج WhatsApp.
2. اربط رقم الشركة واحصل على `Phone Number ID` و `Access Token` دائم.
3. في `.env`:
   ```
   WHATSAPP_DRIVER=cloud
   WA_PHONE_NUMBER_ID=...
   WA_TOKEN=...
   WA_VERIFY_TOKEN=callrent-verify
   WA_APP_SECRET=...
   ```
4. اجعل الخادم متاحاً عبر HTTPS، وسجّل الويبهوك في Meta على:
   `https://your-domain/api/whatsapp/webhook` بنفس `WA_VERIFY_TOKEN`.

**سياسة الإرسال:** `WA_AUTOSEND=false` (الافتراضي) يعني أن النظام يصوغ الرد ويعرضه
كمسوّدة، ولا يُرسل شيء إلا بضغطك على «إرسال». إن فعّلت الإرسال التلقائي، يُرسل فقط
عندما تكون ثقة الرد ≥ 80% ولا يحتاج تدخّل موظف.

## 5) تدريب الردود على أسلوبك

هذا هو الجزء الذي يجعل الردود «بشرية» وبأسلوب شركتك:

1. **ملف هوية الشركة:** `cp config/company.example.md config/company.md` ثم عدّله
   (النبرة، القواعد الممنوعة، المعلومات الثابتة).
2. **الردود المدرَّبة:** من تبويب «الردود المدرَّبة» أضف لكل موضوع (سعر، توفر، تمديد،
   حادث…) الرد المعتمد كما تكتبه أنت. أو الأسهل: بعد أي رد ترسله في محادثة حقيقية،
   اضغط **«احفظ كرد مدرَّب»**.
3. كل رد جديد يُصاغ اعتماداً على: هوية الشركة + الردود المدرَّبة + سياق العميل من
   eganis (عقوده، رصيده، مواعيده) + سياق المحادثة.

كلما زادت الردود المعتمدة، اقترب الأسلوب من أسلوبك. يتطلب هذا `ANTHROPIC_API_KEY`
في `.env`؛ بدونه يبقى كل شيء يعمل عدا الصياغة التلقائية (ترد يدوياً).

## 5.5) محاسبة المستأجرين (التأمينات والمستحقات)

تبويب **«محاسبة المستأجرين»** يجيب على سؤال واحد: *كم لهذا العميل عندنا، أو كم مطلوب منه؟*

**كيف يحسبها النظام:** كل حركة مالية إمّا **لصالح العميل** أو **عليه**، والرصيد النهائي = مجموع ما له − مجموع ما عليه.

| لصالح العميل (يزيد رصيده) | على العميل (ينقص رصيده) |
|---|---|
| `deposit` تأمين مستلم | `rent_charge` أجرة العقد |
| `payment` دفعة نقدية | `damage` تكاليف حادث أو صيانة |
| `discount` خصم | `fine` مخالفة مرورية |
| | `fuel` فرق وقود · `extra` رسوم إضافية |
| | `deposit_refund` تأمين أعدناه له |

**من أين تأتي الحركات:**
- **تلقائياً من eganis:** التأمين والأجرة والدفعات لكل عقد (وإذا وفّر حسابك مساراً لكشف الحساب يُستخدم مباشرة — أضِف `listLedgerEntries` في `config/eganis.json`).
- **يدوياً من التبويب:** ما لا يسجّله eganis — تكاليف الحوادث، المخالفات، إعادة التأمين نقداً، أي تسوية.

**الحالات التي يغطيها:**
- عميل ترك تأمينه عندنا واستأجر مرة أخرى: التأمينات تتراكم في رصيده عبر كل العقود، والرقم النهائي يجمعها كلها.
- عميل عمل حادث: تُسجَّل تكلفة الإصلاح كحركة عليه، فينقلب الرصيد إلى مطالبة ويظهر في «حسابات غير مصفّاة».
- التصفية: زر واحد يسجّل إعادة المبلغ له أو تحصيله منه، فيصبح الرصيد صفراً مع بقاء كل التفاصيل في الكشف.

**الكشف:** يظهر أسفل الشاشة بنص جاهز — انسخه أو أرسله للعميل على واتساب بضغطة (يُحفظ كمسوّدة أولاً).

### إرسال الكشف PDF على واتساب

ثلاثة أزرار في أعلى كشف أي عميل:

| الزر | ماذا يفعل |
|---|---|
| **إرسال PDF على واتساب** | يولّد ملف PDF بهوية الشركة ويضعه في محادثة العميل جاهزاً — تفتح تبويب واتساب وتضغط «إرسال» |
| **فتح / حفظ PDF** | يفتح الملف في تبويب جديد: احفظه أو شاركه مباشرة من زر المشاركة في جوالك |
| **إرسال الكشف نصاً** | نفس الكشف كرسالة نصية بدل ملف |

المسارات: `GET /api/accounting/statement.pdf?q=العميل` (أضِف `&download=1` للتنزيل المباشر)،
و`POST /api/accounting/send-statement` بجسم `{"q":"العميل","as":"pdf","send":true}` للإرسال الفعلي.
وعبر MCP: `statement_pdf` و`send_statement` بخيار `as: "pdf"`.

**كيف يُولَّد الملف:** الخادم يبني صفحة HTML بهوية الشركة ثم يطبعها PDF عبر متصفّح
Chrome/Chromium المثبَّت على الخادم (`--print-to-pdf` المدمج فيه) — بلا أي مكتبة PDF خارجية،
لأن المتصفّح وحده يعالج تشكيل الحروف العربية واتجاه النص معالجة صحيحة.

على الخادم تحتاج شيئين:

```bash
apt install chromium          # أو google-chrome — أو اضبط PDF_CHROME_PATH
apt install fonts-noto-core   # خطوط عربية، وإلا ظهرت الحروف مربّعات فارغة
```

إن لم يوجد متصفّح، يبقى البديل جاهزاً: `GET /api/accounting/statement.html?q=العميل`
صفحة مهيّأة للطباعة تحفظها PDF من متصفّحك.

**الإرسال الفعلي على واتساب** يمرّ عبر WhatsApp Cloud API: يرفع الملف ثم يرسله كمستند
(`sendDocument`)، ويُسجَّل في سجل المحادثة وسجل التدقيق. في الوضع التجريبي (`mock`) يُسجَّل
الإرسال في السجل بلا إرسال فعلي.

**عبر MCP:** `customer_statement` · `open_balances` · `add_ledger_entry` · `settle_customer` · `send_statement`.


## 5.6) الليرة والدولار معاً

عقود الشركة وعملاؤها منهم من يُحاسَب بالليرة ومنهم بالدولار، والنظام يتعامل مع الاثنين في الوقت نفسه.

**القاعدة الأساسية:** كل حركة تبقى **بعملتها التي حدثت بها** ولا تُحوَّل عند التسجيل. التحويل يجري
للعرض والملخّص فقط، بسعر اللحظة، فلا يتغيّر تاريخ الحساب إذا تغيّر السعر لاحقاً.

**ما تراه في التطبيق:**
- كل مبلغ يظهر بالعملتين بالصيغة **«2,820 ₺ / 50 $»** — رصيد الليرة ورصيد الدولار.
  (كل الأرقام في التطبيق والكشوف بالخانات الإنجليزية.)
- تحت الرقم النهائي يظهر **المكافئ الإجمالي** بسعر الصرف الحالي، بالليرة وبالدولار.
- شريط أعلى التبويب يعرض **سعر الصرف المعتمد ومصدره ووقته** مع زر تحديث فوري.
- عميل له رصيد بعملة وعليه مستحقات بالعملة الأخرى يظهر بالطرفين معاً («له… / عليه…») بلا دمج.
- عند إضافة حركة يدوية تختار العملة من القائمة: **ليرة تركية ₺** أو **دولار $**.
- التصفية تُصفّر كل عملة بحركة بعملتها؛ ويمكن تصفية عملة واحدة فقط، أو تسجيل أن الدفع تمّ بعملة
  أخرى (يُذكر المبلغ المستلم فعلاً وسعر الصرف في ملاحظة الحركة).

**سعر الصرف — من أين يأتي:** المصدر الافتراضي **حرم ألتين (haremaltin.com)** — سعر السوق
الذي تعتمده الصرافات وتحاسب عليه الشركة عملاءها، ويؤخذ منه **سعر البيع (satış)** ليطابق ما
يظهر في تطبيق حرم. وإن تعذّر: البنك المركزي التركي (TCMB) ثم `open.er-api.com` ثم
`frankfurter (ECB)`.

السعر يُجلب **تلقائياً عند إقلاع الخادم ثم كل `FX_TTL_MINUTES`** (١٥ دقيقة افتراضياً)، ويُحفظ
في قاعدة البيانات بوقته ومصدره. الواجهة تحدّث الشريط كل دقيقة، وفيه زر تحديث فوري. عند انقطاع
الشبكة يُستخدم آخر سعر محفوظ ويُعلَّم بأنه قديم فلا تتوقف الحسابات.

**للتأكد أن الربط شغّال على خادمك:**

```bash
curl -s "http://localhost:3000/api/fx/check?token=$APP_TOKEN"
```

يجرّب كل المصادر ويقول لك أيها استجاب وأيها محجوب وكم أعطى — أسرع طريقة لتشخيص أي مشكلة شبكة.

**تغيير المصدر أو الحقل:**

```env
FX_SOURCE=harem        # harem | tcmb | erapi | frankfurter | custom
FX_HAREM_FIELD=satis   # satis سعر البيع (الافتراضي) · alis سعر الشراء
FX_AUTO_REFRESH=true
```

وإن أردت مصدراً خاصاً بك (API صرافة تتعامل معها مثلاً):

```env
FX_SOURCE=custom
FX_CUSTOM_URL=https://example.com/rates.json
FX_CUSTOM_PATH=data.USDTRY.satis
FX_CUSTOM_NAME=صرافة الشركة
```

يقرأ النظام الأرقام بالصيغتين التركية (`48,0500`) والإنجليزية (`48.0500`)، ويرفض أي سعر غير
معقول (خارج نطاق ١–١٠٬٠٠٠) حتى لا يدخل رقم مشوّه إلى الحسابات.

**لاعتماد سعر الشركة الخاص** بدل الأسعار الرسمية:

```env
FX_MODE=manual
FX_USD_TRY=41.85
```

أو من الواجهة/الـ MCP عبر `fx_set_rate`. اترك `FX_USD_TRY` مضبوطاً حتى في الوضع المباشر ليكون
احتياطياً عند تعذّر كل المصادر.

**ربط عملة العقود من eganis:** أضف اسم حقل العملة عندك في `config/eganis.json`:

```json
"contract":    { "currency": "currencyCode" },
"ledgerEntry": { "currency": "currencyCode" }
```

يقبل النظام `TRY / TL / ₺ / ليرة` و`USD / $ / دولار`، وأي قيمة أخرى تُعامل كليرة.

**عبر MCP:** `fx_rate` (السعر الآن) · `fx_set_rate` (اعتماد سعر الشركة)، و`add_ledger_entry`
و`settle_customer` يقبلان `currency`.

{

الأدوات المتاحة:

| قراءة | أوامر تنفيذ |

| `list_contracts` / `get_contract` | `close_contract` إغلاق عقد |
| `list_vehicles` / `list_bookings` / `list_tasks` | `set_vehicle_status` حالة مركبة |

## 6.5) فتح التطبيق من الموبايل

الواجهة مصمّمة للموبايل والكمبيوتر معاً (الجداول تتحول إلى بطاقات على الشاشات
الصغيرة)، وتُثبَّت على شاشة الهاتف كأيقونة تطبيق (PWA).

**أ) أسرع طريقة — نفس شبكة الواي فاي (بلا استضافة):**
1. شغّل الخادم على الكمبيوتر: `npm start`
2. اعرف عنوان الكمبيوتر داخل الشبكة:
   - ويندوز: `ipconfig` → قيمة `IPv4 Address` (مثال `192.168.1.20`)
   - ماك/لينكس: `ipconfig getifaddr en0` أو `hostname -I`
3. من الموبايل (على نفس الواي فاي) افتح: `http://192.168.1.20:3000`

**ب) للوصول من أي مكان — استضافة على الإنترنت:**
ارفع المشروع على أي استضافة تدعم Node (Railway، Render، Fly.io، أو خادم VPS)،
واضبط متغيّرات البيئة نفسها الموجودة في `.env`. الخادم يستمع على `0.0.0.0`
والمنفذ يؤخذ من `PORT` تلقائياً، فلا يحتاج أي تعديل. **ملاحظة:** ويبهوك واتساب
يتطلب HTTPS، لذلك الاستضافة ضرورية لتشغيل واتساب فعلياً.

**ج) تثبيته كأيقونة على الشاشة الرئيسية:**
- أندرويد (Chrome): القائمة ⋮ ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية»
- آيفون (Safari): زر المشاركة ← «إضافة إلى الشاشة الرئيسية»

بعدها يفتح بملء الشاشة بلا شريط متصفح، ويحتفظ برمز الدخول فلا تُدخله كل مرة.
(التثبيت على أندرويد يحتاج HTTPS، أي بعد الاستضافة؛ على الواي فاي المحلي يعمل
من المتصفح مباشرة.)

## 7) الأمان

- `APP_TOKEN` يحمي كل المسارات عدا `/api/health` وويبهوك واتساب (المحمي بتوقيع Meta).
- `ALLOW_WRITES=false` يوقف كل أوامر التعديل ويبقي القراءة فقط — مفيد أثناء التجربة.
- كل تعديل أو رسالة مُرسلة تُسجَّل في **سجل الأوامر** مع منفّذها ووقتها.
- بيانات الدخول تبقى في `.env` و `config/eganis.json` — كلاهما مستثنى من Git.
- لا تُشغّل الخادم على الإنترنت بدون HTTPS و `APP_TOKEN` قوي.

## 8) التوسّع لاحقاً (محاسبة، موارد بشرية، تحليلات)

أضف مجلداً جديداً تحت `src/connectors/` بنفس نمط موصل eganis (سائق + واجهة موحّدة)،
ثم مسارات في `src/routes/`، ثم أدوات في `src/mcp/server.js`. البنية مصمّمة لذلك:
كل نظام خارجي = موصل مستقل، والتطبيق يبقى الطبقة الموحّدة فوقها.

## 10) ما تم اختباره فعلياً

- مسارات الـ API كاملة مع الوضع التجريبي (`mock`) ✅
- أوامر التعديل + تسجيلها في سجل التدقيق ✅
- خادم MCP: سرد الأدوات وتنفيذها ✅
- لوحة التحكم بكل تبويباتها ✅ (بلا أخطاء في المتصفح)
- محاسبة العملتين: فصل الأرصدة، العرض المزدوج، التحويل بسعر محدّد، التصفية لكل عملة ✅
- توليد كشف الحساب PDF فعلياً (عربي صحيح التشكيل والاتجاه) وحفظه وإرساله في المحادثة ✅
- **لم يُختبر:** الاتصال الفعلي بـ eganis وواتساب وصياغة الردود — تحتاج بيانات
  حسابك ومفاتيحه. وكذلك **جلب سعر الصرف المباشر** من حرم ألتين وبقية المصادر: بيئة التطوير
  المستخدَمة في البناء تمنع الخروج للإنترنت (كل المصادر تُرجع 403 من بروكسي البيئة)، فتأكيده
  يتم على خادمك بأمر واحد: `GET /api/fx/check`. أما تحليل استجابة حرم ألتين وقراءة الأرقام
  بالصيغة التركية فمُختبَران باختبارات وحدة، والوضع اليدوي والسعر المحفوظ يعملان بلا شبكة.
